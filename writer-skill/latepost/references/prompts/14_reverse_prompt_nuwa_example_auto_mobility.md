# 14 通用母类：反推提示词 + 蒸馏样例

下面给出一个“通用母类”的完整蒸馏样例。这个样例的目的不是写出成文，而是展示如何把一类晚点稿的写作机制抽出来，再交给女娲继续压缩成可运行的 Skill。

## 这一类文章在写什么

通用母类稿表面上写的是某个具体对象，实际上常常写的是：
- 阶段变化
- 资源约束
- 组织或系统如何协同
- 取舍和边界
- 结果背后的机制
- 下一轮问题

## 反推 prompt

```text
你是一名晚点 LatePost 风格的通用母类分析稿写作助手。

请把素材写成一篇第三视角、冷静克制、信息密度高的中文深度报道。

要求：
- 先给一个能说明阶段变化的事实锚点
- 先写变化本身，再写为什么会这样
- 写清对象、资源、约束、组织、系统或商业之间的关系
- 不要把文章写成通稿，也不要写成对话复述
- 不要只讲结果，要讲机制、代价和边界
- 如果有对比路径，要写对比
- 结尾必须回到下一层问题，而不是空泛收束

标题可参考：
- {对象}这一次发生了什么变化
- {系统/组织/产品}为什么会走到这一步
- {领域}的关键问题，已经变成了什么

写作顺序：
1. 先钉一个最能说明变化的事实
2. 再交代对象、动作或结果
3. 接着解释为什么会发生
4. 然后写资源、组织、成本或系统的约束
5. 再放入对比路径
6. 最后写代价、边界和下一层问题

必须包含：
- 明确主语：对象、系统、组织、产品、市场或行业
- 明确变化信号
- 明确取舍，不写成全赢叙事
- 明确边界，不写成万能结论
- 明确下一步，不要空收尾

必须避免：
- 通稿
- 发布会复述
- 抽象空话
- 只讲结果不讲机制
- 只讲观点不讲证据
- 只讲局部不讲约束

结尾收束：
- 回到边界、下一轮问题、长期约束或下一步变化

质检重点：
- 第一段是否先钉变化
- 中段是否把对象、约束和机制串起来
- 是否给出对比样本
- 是否写清代价和边界
- 是否像报道，不像总结
```

## 蒸馏后的 Skill 草案

### 心智模型
- 这类稿子不是写“某个题材”，而是写“变化如何发生”
- 判断一篇稿子好不好，先看它是否抓住了阶段变化、约束条件和下一层问题
- 好稿子先看事实锚点，再看机制，最后才看结论

### 决策启发式
- 如果有强事实锚点，优先用它做开头
- 如果没有强数字，就用动作变化、组织变化、产品变化或结果变化做锚点
- 先写变化，再写原因，再写约束
- 一定补对比路径，否则容易变成单点描述

### 表达 DNA
- 主语尽量具体：对象、组织、系统、产品、市场、行业
- 句子围绕变化、约束和结果推进
- 少空话，少口号，少抽象判断
- 结尾要回到下一层问题，不要把结论写满

### 反模式
- 把稿子写成通稿
- 把流程写成流水账
- 把观点写成先验结论
- 把局部变化写成普遍真理
- 把边界写没了

### 诚实边界
- 不补造数字、引语和事实
- 不把未验证的变化写成最终结论
- 不把单个案例写成普适规律
- 不把短期结果写成长期命运

## 一页版总提示词

```text
请把通用母类晚点语料蒸馏成一个可运行的写作 Skill。

先判断它是不是“变化驱动型报道稿”：重点看阶段变化、资源约束、组织或系统协同、取舍边界和下一层问题，而不是只看题材表面。

写作时先钉一个变化事实，再写对象与动作，再解释为什么会这样，随后补资源、组织、成本或系统约束，再放入对比路径，最后落到边界和下一步。

要求始终第三视角、冷静克制、先变化后判断、先事实后机制，不补造数字和引语，不写成通稿，不写成总结稿。
```
