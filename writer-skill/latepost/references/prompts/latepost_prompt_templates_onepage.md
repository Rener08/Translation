# 晚点 Prompt 一页版（3 类主表）

> 直接复制就能用。这里只保留 3 个默认主场景，减少模型分心。
> 正文篇幅是软提示：尽量控制在原文长度的 40% - 65% 区间，不作为硬字数门槛。
> 段落标题长度单独约束，不要和正文篇幅混在一起。

## 1）访谈 / 播客 / 字幕同步稿
把素材写成晚点式访谈同步稿。要求：第三视角、冷静克制、信息密度高；先钉说了什么，再写为什么重要；尽量保留问答节奏和人物差异；不要把逐字稿写成流水账。结尾回到人物、判断或组织含义。

标题可参考：
- `{人物/节目}访谈：{一个关键判断}`
- `{嘉宾}讲了什么，为什么这件事重要？`
- `{主题}背后，真正被讨论的是什么`

## 2）产品 / 实测 / 评测
把素材写成晚点式产品实测稿。要求：先写一个真实任务，最好带人物、动作、场景或时间；写清执行过程、纠错过程、失败点；对比演示效果和真实可用性；少讲宣传词，多讲边界。结尾落到产品边界和形态变化。

标题可参考：
- `{产品名}实测：它到底能不能替你干活`
- `{公司}的新产品，解决了什么，也暴露了什么`
- `{产品/Agent}从演示到可用，还差哪一步`

## 3）基础设施 / 云 / 模型 / 平台
把素材写成晚点式基础设施稿。要求：先给拐点或规模数字；解释为什么竞争从单点能力变成全栈能力；写清资源、算力、数据、平台、商业化关系；少空话，重点写代价和边界；第三视角要写成报道视角，不要沿着人物发言顺序逐条复述。结尾用长期主义、成本或下一层问题收束。

标题可参考：
- `{公司}在{模型/云/平台}上押的是什么`
- `{行业}的竞争，为什么开始拼全栈`
- `{规模/成本}之后，真正的门槛是什么`

## 总提示词
用晚点 LatePost 的中文深度报道口吻写作：第三视角、冷静克制、连贯叙事；先钉具体变化，再自然给判断；先写变化，再写机制；多用具体人名、公司名、产品名、时间、数字；少空话、少口号、少概念堆砌；像记者写报道，而不是像宣传稿。

## 反向提示词
不要写成通稿、空话总结、官方宣传、纯抽象分析、术语堆砌、时间线流水账；不要把小标题写成完整句子或口号；不要只讲结果不讲机制，不要只讲观点不讲证据。
