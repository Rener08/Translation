# 晚点内容方法论

## 1. 先看变化，再看机制

晚点稿件的第一优先级不是“讲得多”，而是“讲清楚变化发生在哪里”。

先回答三个问题：
- 发生了什么变化
- 为什么现在发生
- 这件事会把代价推向哪里

如果一段素材只是在重复观点、评价或态度，但没有变化锚点，就不适合直接写成晚点稿。

## 2. 结构先于文采

文章优先按下面的顺序组织：
- 开头先给事实锚点或拐点
- 中段写机制、流程、资源和组织变化
- 结尾收回边界、代价和下一层问题

文采可以有，但不能抢结构。

## 3. 用可核实信息撑起叙事

优先使用：
- 公司名、产品名、组织名
- 时间点、规模、数量、比例
- 可核实的动作、流程、公开表述

少用：
- 空泛判断
- 没有锚点的抽象结论
- 没有来源支撑的“行业共识”

## 4. 只保留三类默认主场景

晚点的默认可见面只保留三类：
- 访谈 / 播客 / 字幕同步稿
- 产品 / 实测 / 评测
- 基础设施 / 云 / 模型 / 平台

其余题材都应该先进入扩展参考，而不是默认主表。

## 5. 结论要落回代价与边界

晚点稿件的结尾，不是重复开头，而是回答：
- 这套变化能持续多久
- 它依赖什么条件
- 谁承担新增成本
- 下一层竞争会在哪里发生

## 6. 反面例子

不适合晚点的写法包括：
- 先大结论、后补材料
- 一路抽象到没有事实
- 只写功能，不写组织和流程
- 只写情绪，不写结构

晚点不是宣传稿，也不是评论短文，而是以事实、机制和边界为核心的深度报道。
